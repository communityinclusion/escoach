# Bootstrap Barrio Subtheme

## Overview

Use this skill when you need to create or maintain a custom Drupal theme that extends `bootstrap_barrio` using the Bootstrap 4/5 Sass subtheme base and the installation shell script documented by Drupal.org.

This skill focuses on:
- Using the official Bootstrap 4/5 Sass subtheme base
- Running the installation shell script from the installation guide
- Creating a custom subtheme in `web/themes/custom/`
- Updating theme machine name and metadata safely
- Setting up Sass/Gulp asset compilation
- Enabling and validating the subtheme in Drupal

## When to Use This Skill

Invoke this skill when working with:
- New Barrio subtheme creation
- Migration to the Bootstrap 4/5 Sass subtheme base
- Adjusting Barrio/Bootstrap variables in a subtheme
- Fixing missing styles/scripts in a Barrio-based theme
- Standardizing Barrio build tooling (`npm`, `gulp`) in DDEV

## Recommended Subtheme Workflow

### 1. Ensure bootstrap_sass is installed

The `bootstrap_sass` contrib theme ships the installer script. It must be present at `web/themes/contrib/bootstrap_sass/scripts/create_subtheme.sh`.

```bash
ddev composer require drupal/bootstrap_sass
```

### 2. Run the installation shell script

The script lives inside the `bootstrap_sass` contrib theme. Run it from inside the DDEV container, targeting the script path. It will interactively prompt for two values.

```bash
ddev exec bash web/themes/contrib/bootstrap_sass/scripts/create_subtheme.sh
```

When prompted:

```
The machine name of your custom theme? [e.g. mycustom_bootstrap_sass]
> my_subtheme

Your theme name ? [e.g. My custom bootstrap_sass]
> My Subtheme Name
```

**What the script does internally:**

1. Creates `web/themes/custom/` if it does not exist
2. Copies `web/themes/contrib/bootstrap_sass/` to `web/themes/custom/<machine_name>/`
3. Renames all top-level files: `bootstrap_sass.*` → `<machine_name>.*`
4. Renames all config files: `config/*/*bootstrap_sass*.*` → `config/*/*<machine_name>*.*`
5. Removes `scripts/create_subtheme.sh` from the new theme (not needed in the subtheme)
6. Runs a recursive `sed` find/replace of every `bootstrap_sass` token with `<machine_name>` across all files
7. Updates the `name:` value in `<machine_name>.info.yml` from `SASS Bootstrap Starter Kit Subtheme` to the human-readable name provided

**Files produced in `web/themes/custom/<machine_name>/`:**

```
<machine_name>.info.yml
<machine_name>.libraries.yml
<machine_name>.theme
config/
  install/
    <machine_name>.settings.yml
  schema/
    <machine_name>.schema.yml
css/              ← compiled output (generated by gulp)
js/               ← copied Bootstrap/Popper/Barrio JS (generated by gulp)
scss/
  import.scss     ← full Bootstrap component import list
  style.scss      ← entry point, imports import.scss + custom styles
  variables.scss  ← Bootstrap variable overrides
  typography.scss ← font imports and font variable overrides
  mixins.scss     ← custom mixins
images/
templates/
gulpfile.js
package.json
```

### 3. Verify generated files

After the script completes, confirm:

- `web/themes/custom/<machine_name>/<machine_name>.info.yml` has `base theme: bootstrap_barrio`
- All references to `bootstrap_sass` have been replaced with the machine name
- `config/install/<machine_name>.settings.yml` exists (seeds Barrio theme settings on enable)
- `config/schema/<machine_name>.schema.yml` exists

### 4. Install front-end dependencies

```bash
ddev exec "cd web/themes/custom/<machine_name> && npm install"
```

### 5. Compile assets

Build CSS and copy Bootstrap/Popper JS into the theme's `js/` directory:

```bash
# Compile SCSS → CSS only
ddev exec "cd web/themes/custom/<machine_name> && gulp styles"

# Copy Bootstrap/Popper/Barrio JS files into js/
ddev exec "cd web/themes/custom/<machine_name> && gulp js"

# Full build (styles + js, then BrowserSync watch — for local development)
ddev exec "cd web/themes/custom/<machine_name> && gulp"
```

> **Note:** The default `gulp` task runs `styles` then starts a `serve` (BrowserSync watch) process. For CI or one-shot builds use `gulp styles && gulp js`. There is no standalone `gulp watch` task — watch is built into `gulp serve`.

**SCSS entry point (`style.scss`)** imports `import.scss`, which contains the full Bootstrap component list in the correct order (functions → variables override → Bootstrap variables → maps → mixins → root → components → utilities API → custom). Edit `import.scss` to add or remove Bootstrap components.

### 6. Update BrowserSync proxy

Edit `gulpfile.js` and change the BrowserSync proxy URL to your local DDEV site before using the watch/serve mode:

```js
browserSync.init({
  proxy: 'https://<project-name>.ddev.site',
});
```

### 7. Enable and set default theme

```bash
ddev drush theme:enable <machine_name> -y
ddev drush config:set system.theme default <machine_name> -y
ddev drush cr
```

## Asset and Library Rules

- Keep all custom CSS/JS in the subtheme, not in contrib Barrio files
- Ensure `.libraries.yml` paths match built asset locations exactly
- Commit source Sass files; decide team policy for compiled CSS commits
- Use `variables.scss`, `typography.scss`, and `imports.scss` references from the official docs when structuring overrides
- Prefer Bootstrap/Barrio variables and utility classes before large custom overrides

### Import Order (Critical)

The order of imports in `import.scss` is the source of truth. The entry point `style.scss` simply calls `@import "import"` plus any custom page-level overrides.

```scss
// import.scss — full Bootstrap component list in required order

// 1. Functions first (color manipulation, calc, etc.)
@import "../node_modules/bootstrap/scss/functions";

// 2. Variable overrides BEFORE Bootstrap variables
@import "variables";
@import "typography";

// 3. Bootstrap variables and dark mode variables
@import "../node_modules/bootstrap/scss/variables";
@import "../node_modules/bootstrap/scss/variables-dark";

@import "../node_modules/bootstrap/scss/maps";

@import "../node_modules/bootstrap/scss/utilities";
```

**`style.scss`** — entry point that imports the above and adds page-level overrides:

```scss
// style.scss
@import "import";

// Custom page-level overrides below
a { color: $accent-shade; }
.bg-inverse { background: $primary-shade !important; }
.site-footer { background: $accent-shade !important; }
```

> `style.scss` is the Gulp source entry point (`paths.scss.src`). Bootstrap itself is also compiled separately via `paths.scss.bootstrap` in the Gulp `styles()` task — both are piped together.

### Responsive Breakpoints

#### Default Breakpoints

Bootstrap includes six default breakpoints:

| Breakpoint | Class Infix | Dimensions |
|------------|-------------|------------|
| Extra small | None | <576px |
| Small | `sm` | ≥576px |
| Medium | `md` | ≥768px |
| Large | `lg` | ≥992px |
| Extra large | `xl` | ≥1200px |
| Extra extra large | `xxl` | ≥1400px |

#### Breakpoint Sass Map

```scss
// Default Bootstrap breakpoints (in _variables.scss)
$grid-breakpoints: (
  xs: 0,
  sm: 576px,
  md: 768px,
  lg: 992px,
  xl: 1200px,
  xxl: 1400px
);
```

#### Customizing Breakpoints

Override in your `_variables.scss` BEFORE importing Bootstrap's variables:

```scss
// Custom breakpoints
$grid-breakpoints: (
  xs: 0,
  sm: 576px,
  md: 768px,
  lg: 992px,
  xl: 1200px,
  xxl: 1400px,
  xxxl: 1600px  // Add custom breakpoint
);

// Matching container max-widths
$container-max-widths: (
  sm: 540px,
  md: 720px,
  lg: 960px,
  xl: 1140px,
  xxl: 1320px,
  xxxl: 1500px  // Match custom breakpoint
);
```

#### Media Query Mixins

```scss
// Min-width (mobile first) — styles apply from breakpoint UP
@include media-breakpoint-up(md) { ... }

// Max-width (desktop first) — styles apply from breakpoint DOWN
@include media-breakpoint-down(md) { ... }

// Single breakpoint only
@include media-breakpoint-only(md) { ... }

// Between two breakpoints
@include media-breakpoint-between(md, xl) { ... }
```

#### Practical Breakpoint Examples

```scss
// Responsive typography
.page-title {
  font-size: 1.5rem;

  @include media-breakpoint-up(md) { font-size: 2rem; }
  @include media-breakpoint-up(lg) { font-size: 2.5rem; }
}

// Responsive grid
.card-grid {
  display: grid;
  gap: 1rem;
  grid-template-columns: 1fr;

  @include media-breakpoint-up(sm)  { grid-template-columns: repeat(2, 1fr); }
  @include media-breakpoint-up(lg)  { grid-template-columns: repeat(3, 1fr); gap: 1.5rem; }
  @include media-breakpoint-up(xl)  { grid-template-columns: repeat(4, 1fr); }
}
```

> **Note:** CSS custom properties (`var()`) cannot be used in media queries. Always use the Sass mixins above for breakpoints.

```scss
$custom-colors: (
```

```scss
$theme-colors: map-remove($theme-colors, "info", "light");
```

### Barrio Material Design Color System

Bootstrap Barrio uses a **Google Material Design** color management concept to generate the full Bootstrap color scheme from just two seed colors: a **primary** and an **accent**.

> These variables are **not** used directly as markup classes. They generate a custom Bootstrap color palette via `$theme-colors`. Define them in `variables.scss`, then let Bootstrap produce all derived utility classes, component variants, and state colors automatically.

#### Defining Primary and Accent Seeds

```scss
// variables.scss

/* VARIABLES */

// Primary color — defines the main brand/secondary tone
$primary-shade: #A8CF45;
$primary-light: lighten($primary-shade, 37%);
$primary-dark:  darken($primary-shade, 12%);

// Accent color — defines the primary/action tone
$accent-shade: #0079C0;
$accent-light: lighten($accent-shade, 37%);
$accent-dark:  darken($accent-shade, 12%);
```

#### Mapping Seeds to Bootstrap Theme Colors

Apply the seed variables to Bootstrap's `$theme-colors` map:

```scss
// variables.scss (after defining seeds, before @import bootstrap)

$theme-colors: (
  primary:   $accent-shade,   // Action/interactive color
  secondary: $primary-shade,  // Brand/supporting color
  success:   $green,
  info:      $cyan,
  warning:   $yellow,
  danger:    $red,
  light:     $primary-light,
  dark:      $primary-dark,
);
```

#### Third Corporate Color — Adding `tertiary` to `$theme-colors`

> **Bootstrap 5.3 naming conflict to be aware of:** Bootstrap 5.3 introduced built-in CSS variables `--bs-tertiary-color` and `--bs-tertiary-bg` on `:root`. These are **semantic surface variables** (for lighter text, hover backgrounds, and wells) — they are **not** a brand action color in `$theme-colors`. A custom brand `tertiary` added via `map-merge` lives separately in `$theme-colors` and generates its own set of utility classes.

If the brand provides a third corporate color, declare its seed variables and extend `$theme-colors` via `map-merge`:

```scss
// variables.scss

$tertiary-shade: #F4A11A;
// Use tint-color()/shade-color() — they use mix() for more complete tonal range
// than lighten()/darken() which only adjust lightness
$tertiary-light: tint-color($tertiary-shade, 37%);
$tertiary-dark:  shade-color($tertiary-shade, 12%);

// Extend theme colors map (after $theme-colors is defined)
$custom-colors: (
  "tertiary": $tertiary-shade,
);
$theme-colors: map-merge($theme-colors, $custom-colors);
```

This generates `.bg-tertiary`, `.text-tertiary`, `.btn-tertiary`, `.btn-outline-tertiary`, and all derived utility classes automatically.

Bootstrap 5.3 also auto-generates these CSS variables for each `$theme-colors` entry (including custom ones):

```scss
--bs-tertiary           // base color
--bs-tertiary-rgb       // for rgba() usage
--bs-tertiary-bg-subtle
--bs-tertiary-border-subtle
--bs-tertiary-text-emphasis
```

#### Additional Brand Colors

For each subsequent corporate color, follow the same pattern — name it descriptively with a seed variable and extend `$theme-colors` in a single `map-merge` batch:

```scss
// variables.scss

$tertiary-shade:  #F4A11A;
$brand-highlight: #E8003D;
$brand-neutral:   #6B6B6B;

$custom-colors: (
  "tertiary":  $tertiary-shade,
  "highlight": $brand-highlight,
  "neutral":   $brand-neutral,
);
$theme-colors: map-merge($theme-colors, $custom-colors);
```

> Keep named color variables (`$tertiary-shade`, `$brand-highlight`, etc.) as the single source of truth. Never hard-code hex values in component SCSS — always reference the variable.

> Use `tint-color()` and `shade-color()` (which use `mix()`) rather than `lighten()`/`darken()` for generating color variants. Bootstrap's own palette is built this way and produces a more complete tonal range.

#### Gray Scale Assignments

If the brand specifies gray values, map them to Bootstrap's named gray variables to ensure consistent use across utility classes and components:

```scss
// variables.scss

// Light gray → backgrounds, dividers, subtle surfaces
$gray-200: #EBEBEB;  // override with brand value

// Dark gray → body text, borders, secondary text
$gray-800: #3A3A3A;  // override with brand value
```

Bootstrap derives `$body-color`, `$border-color`, and many component defaults from the gray scale. Overriding `$gray-200` and `$gray-800` propagates consistently without additional variable work.

Common mappings to confirm after overriding grays:

| Bootstrap variable | Typical source | Use |
|---|---|---|
| `$body-color` | `$gray-900` | Default body text |
| `$body-bg` | `$white` / `$gray-100` | Page background |
| `$border-color` | `$gray-300` | Component borders |
| `$text-muted` | `$gray-600` | Secondary/muted text |
| `$light` (theme color) | `$gray-100` | Light backgrounds |

If the brand gray is significantly different from Bootstrap defaults, also override `$gray-300` (borders) and `$gray-600` (muted text) to maintain the intended visual hierarchy.

#### Workflow — Always Start Here

1. Choose a `$primary-shade` (brand/secondary tone) and `$accent-shade` (primary/action tone)
2. Declare `light`/`dark` variants via `lighten()`/`darken()`
3. Map both seeds into `$theme-colors` as shown above
4. If a third (or more) corporate color exists, add it as a named seed and extend `$theme-colors` via `map-merge`
5. Override `$gray-200` (backgrounds) and `$gray-800` (text/borders) with brand gray values if provided
6. Bootstrap generates all utility classes, component variants, and state colors from this map
7. Do **not** hard-code colors elsewhere in the theme — reference `$primary`, `$secondary`, `$tertiary`, etc.

### Typography — `typography.scss`

All font imports and base font variables belong in `typography.scss`. This file is imported in `imports.scss` before Bootstrap variables so the font families are available as overrides.

```scss
// typography.scss

/* TYPOGRAPHY */

/* Google Fonts — uncomment to activate */
//@import url("https://fonts.googleapis.com/css?family=Lato:400,300,300italic,400italic,700,700italic,900,900italic");
//@import url("https://fonts.googleapis.com/css?family=Raleway:400,300,500,600,700,800,900");

// Custom font family variables
$font-lato: 'Lato', Arial, Verdana, sans-serif;
$font-raleway: 'Raleway', Arial, Verdana, sans-serif;

// Bootstrap base font stack overrides
$font-family-sans-serif:
  -apple-system,
  system-ui,
  BlinkMacSystemFont,
  "Segoe UI",
  Roboto,
  "Helvetica Neue",
  Arial,
  sans-serif !default;

$font-family-serif:
  Georgia,
  "Times New Roman",
  Times,
  serif !default;

$font-family-monospace:
  Menlo,
  Monaco,
  Consolas,
  "Liberation Mono",
  "Courier New",
  monospace;

// Set the active base font family
$font-family-base: $font-family-sans-serif;
```

> To use a Google Font as the site font, import it at the top of `typography.scss`, define a variable (e.g. `$font-lato`), then assign it: `$font-family-base: $font-lato;`

### Markup Styles — `style.scss`

Component-level and page-layout overrides go in `style.scss`. Keep this file focused on structural and visual adjustments that are not achievable through Bootstrap variable overrides alone.

## Bootstrap Barrio Settings Reference

Every subtheme that extends `bootstrap_barrio` should ship a `config/install/<my_subtheme>.settings.yml` file. This file seeds the theme settings when the theme is first enabled and avoids the need for manual configuration through the UI. All keys below are prefixed `bootstrap_barrio_` and are inherited from the base theme schema.

### Minimal bootstrap_sass / newworks baseline

The `bootstrap_sass` starter subtheme and the `newworks` reference theme ship the same baseline. Use this as the starting point for any new subtheme `config/install/<my_subtheme>.settings.yml`:

```yaml

bootstrap_barrio_library: 'production'

bootstrap_barrio_sidebar_first_offset: 0

bootstrap_barrio_sidebar_second_offset: 0

bootstrap_barrio_fluid_container: 0
```

### Schema for Custom Subtheme

Each subtheme must declare its own schema file at `config/schema/<my_subtheme>.schema.yml` to validate the inherited settings. The minimal pattern:

```yaml
# Schema for the configuration files of <My Subtheme>.

<my_subtheme>.settings:
  type: bootstrap_barrio.settings
  label: '<My Subtheme> settings'
```

## Bootstrap and Barrio Override Strategy

1. Start with Barrio settings (`config/install/<my_subtheme>.settings.yml`) and Bootstrap variables
2. Add component-level overrides in subtheme Sass partials
3. Keep selector specificity low; avoid `!important` unless required
4. Validate responsive behavior at Bootstrap breakpoints

## DDEV-First Commands

```bash
# Run the subtheme creation script
ddev exec bash web/themes/contrib/bootstrap_sass/scripts/create_subtheme.sh

# Install front-end dependencies
ddev exec "cd web/themes/custom/<machine_name> && npm install"

# Compile SCSS → CSS
ddev exec "cd web/themes/custom/<machine_name> && gulp styles"

# Copy Bootstrap/Popper/Barrio JS into js/
ddev exec "cd web/themes/custom/<machine_name> && gulp js"

# Clear Drupal caches
ddev drush cr

# Verify active theme
ddev drush config:get system.theme default
```

## Troubleshooting

### Theme not visible in Appearance UI

- Check `.info.yml` syntax and machine name
- Confirm `base theme: bootstrap_barrio`
- Run `ddev drush cr`

### CSS/JS not loading

- Confirm `gulp styles` and `gulp js` have both been run — the `css/` and `js/` directories must be populated
- Validate paths in `<machine_name>.libraries.yml` match built asset filenames (note: Gulp outputs both `style.css` and `style.min.css`)
- Clear caches after every library path change

### Gulp/Sass build fails

- Reinstall dependencies: `ddev exec "cd web/themes/custom/<machine_name> && rm -rf node_modules && npm install"`
- Confirm `sass` package version is `^1.45.0` or higher in `package.json`
- Sass deprecation warnings from Bootstrap are expected and harmless — build still succeeds

### `gulp serve` / BrowserSync not connecting

- Update the `proxy` value in `gulpfile.js` to your actual DDEV site URL before running `gulp serve`
- The default proxy `https://www.drupal.org` must be changed to `https://<project-name>.ddev.site`

### Subtheme creation script fails or leaves `bootstrap_sass` tokens

- Verify the script ran from inside the DDEV container: `ddev exec bash ...`
- Re-run: `grep -r "bootstrap_sass" web/themes/custom/<machine_name>/` to find any un-replaced tokens
- The `sed` in-place replacement uses `-i -e` syntax which is POSIX-compatible inside the container

### Subtheme breaks after Barrio update

- Diff your subtheme's `scss/import.scss` against the updated `bootstrap_sass` import order
- Check `gulpfile.js` source paths — Barrio JS path `../../contrib/bootstrap_barrio/js/barrio.js` must still resolve correctly
- Avoid editing contrib files directly to simplify upgrades
